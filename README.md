# Anamorphic codes – proof-of-concept implementation

> 
> **AI use.** Claude Code
> (Sonnet 5.5) was used to extend and refactor previous manual implementations
> and demo programs, to generate benchmark code, tests and documentation (like this one). All content was
> reviewed by me.

C implementations of pseudorandom codes (PRCs), their anamorphic modes, random
linear network coding (RLNC) and wiretap codes.

## Layout

| Path | Content |
|---|---|
| `prcs/zerobit/` | Zero-bit PRC interface and implementations: LDPC (`prc_ldpc`), permuted puzzle (`prc_pp`), (deletion channel (`prc_dc`); legacy, not part of the thesis) |
| `prcs/multibit/` | Multibit PRC interface and implementations: `PRC^1_adapt`, `PRC_low`, `PRC_high`, and the re-encoding constructions `PRC_sharp` / `PRC_cca` |
| `prcs/anamorphism/` | Anamorphic modes: native LDPC mode (second parity-check matrix) and the generic construction from randomness recovery (`aprc_rr`) |
| `rlnc/` | RLNC over GF(2^m) (`rlnc.c`), its anamorphic mode (`arlnc.c`), extension-field arithmetic (`gf_ext.c`) and the table of irreducible polynomials (`gf_irreducible.h`, generated by `gen_gf_irreducible.py`) |
| `wiretap/` | Wiretap code (OAEP4 with a configurable ECC) |
| `utils/` | Shared helpers: GF(2) matrices (M4RI), randomness sources, CSPRG and symmetric encryption (libsodium), ECCs (Hamming(7,4), none) |
| `demo_*.c` | Command line demo for each code, see [README_demos.md](README_demos.md) |
| `bench.c`, `results/` | Benchmark of anamorphic versus regular operations and recorded results |
| `tests/` | Unit tests and a smoke test of all demos |

## Build

Requires CMake (≥ 3.16), a C11 compiler, libsodium and M4RI (`libm4ri-dev` on
Debian/Ubuntu). OpenSSL is optional and only needed for the wiretap code.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

## Tests

```sh
ctest --test-dir build
```

This runs the unit tests (zero-bit and multibit PRCs, anamorphic lifting,
randomness-recovery anamorphism, RLNC, wiretap) and the demo smoke test.

## Demos

Every code has a demo program `build/demo_<code>` with commands for key
generation, regular and anamorphic encoding and decoding. Usage, parameters,
key and message formats are described in [README_demos.md](README_demos.md).

## Benchmark

```sh
build/bench [--keys K] [--ops N] [--codes LIST] [--param CODE:NAME=VALUE]... [--csv FILE]
```

For each code, `bench` measures key generation, encoding and decoding in the
regular and the anamorphic mode with random messages, and reports timing
statistics, the anamorphic overhead and ciphertext sizes. Results from one
machine are in [results/benchmark.txt](results/benchmark.txt); see
[README_demos.md](README_demos.md) for details.
